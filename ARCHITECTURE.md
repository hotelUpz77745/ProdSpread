# 🧠 Архитектура HFT Спредера (Mental Map)

Проект представляет собой высокочастотного арбитражного бота (Hedge/Spread), торгующего синтетический спред между двумя криптобиржами (в основном Binance и Kucoin) в режиме **Hedge Mode**. Бот написан на асинхронном Python (`asyncio`) с использованием `Numba` для ускорения математических вычислений.

---

## 🏗 Основные слои (Сверху-вниз)

### 1. 🎛 Оркестратор (`main.py`)
Точка входа и главный бесконечный цикл.
- Поднимает WebSocket-соединения (публичные стаканы и приватные позиции).
- Инициализирует REST API клиенты для ордеров.
- В бесконечном цикле (задержка `MAIN_LOOP_DELAY = 0.005` сек):
  - Пересчитывает стаканы и ищет лучший математический спред.
  - Если сигнал есть -> Вызывает `execute_open()` (Вход в сделку).
  - Мониторит открытые сделки -> Вызывает `execute_close()` (Выход).
- Реализует логику аварийных выходов (если одна нога не исполнилась) и систему карантина для проблемных монет (бан на `3600` секунд).

### 2. 🧠 Математическое ядро (`CORE/`)
Критический слой, отвечающий за расчеты и принятие решений.
- **`math_core.py`**: Ускорен с помощью `@njit(fastmath=True)` (Numba). Рассчитывает VWAP (средневзвешенную цену) по стакану с учетом `trade_size_usd`, рассчитывает ожидаемое проскальзывание. Вычисляет текущий математический спред между биржами.
- **`trading_engine.py`**: Принимает сырые стаканы и возвращает "сигнал". `evaluate_entry` — оценивает, пробивает ли спред `spread_rule_enter`. `evaluate_exit` — оценивает, достиг ли спред цели выхода с учетом динамического затухания `decay_map`.
- **`position_manager.py`**: Следит за тем, сколько позиций открыто, не превышен ли лимит по марже (`max_positions`), ставит "блокировки" (locks), чтобы бот не вошел в одну монету дважды одновременно.
- **`leverage_setter.py`**: Скрипт-инициализатор. При запуске обходит все валидные монеты и жестко ставит им нужный режим маржи (`CROSS` / `ISOLATED`) и плечо (`leverage: 10`).

### 3. 🌐 API Интерфейсы (`API/`)
Общение с биржами по REST и WSS.
- **`orders.py`** (`BinanceOrder`, `KucoinOrder`): Унифицированный интерфейс для выставления ордеров. Строго формирует параметры для **Hedge Mode** (передача `positionSide="LONG"/"SHORT"` и `closeOrder=True`). Обрабатывает математическое округление лотов (исправленный баг с научной нотацией float).
- **`discovery.py`**: Парсит все рынки с Binance и Kucoin, отфильтровывает монеты с низким объемом (`volume < 5000000`), собирает пересечения монет и строит `Topology` (например, 77 валидных монет на 2 биржах).
- **`ws_public_*.py`**: Подписывается на глубину стакана (Orderbook top 5). Данные летят прямо в память оркестратора `self.books`.
- **`ws_private_*.py`**: Подписывается на обновления позиций и баланса. Крайне важно для мгновенного определения `fill_rate` (процента исполнения), не дожидаясь ответа REST API.

### 4. 📊 Аналитика и Логи (`analytics.py`, `c_log.py`)
- **`analytics.py`**: Собирает данные о входе и выходе. Рассчитывает точный PnL (Profile and Loss) в долларах, с учетом фактически исполненного объема (`long_executed_usd`), отнимает комиссию тейкера (`taker_fee * 2` за вход и выход). Пишет историю в JSON файлы.
- **`c_log.py`**: Кастомный потокобезопасный логгер с записью в файл `logs/all.log`.

## 🔄 Жизненный цикл сделки (Вход и Выход)

1. **Поиск:** `math_core.py` находит, что BTRUSDT стоит $0.211 на Binance и $0.214 на Kucoin. Спред > 1%.
2. **Сигнал:** `trading_engine.py` дает добро на вход. `position_manager` лочит монету.
3. **Отправка ордеров (IOC):** `orders.py` шлет параллельно (через `asyncio.gather`):
   - LONG по маркету (или агрессивному лимиту) на Binance.
   - SHORT по маркету на Kucoin.
4. **Проверка исполнения:** Если Kucoin отбил ордер с ошибкой, оркестратор видит дисбаланс по позициям (Binance `L: 99.8%`, Kucoin `S: 0.0%`).
5. **Аварийный выход:** Оркестратор кидает монету в карантин, отправляет на Binance ордер SELL `positionSide="LONG"`, чтобы экстренно закрыть ногу и зафиксировать минимальный убыток на разнице спреда (вместо риска полного краха депозита).
6. **Отчет:** `analytics.py` фиксирует убыток (спред + комиссии) на базе реальных исполненных USD.

# Отчет: Калибровка интерпретаторов WS, точечных REST GET и сквозная верификация

## 1. Исправления в пайплайне FSM (`CORE/position_fsm.py`)
- **Строгий `await` перед паузой:**
  Параллельная отправка ордеров `await asyncio.gather(*tasks)` теперь строго дожидается ответа матчинг-движков обеих бирж. Только после полного завершения отправки запускается пауза ожидания в стакане `await asyncio.sleep(self.execution_pause)` (`0.030` сек).
- **Разделение зон ответственности (WebSocket vs REST):**
  - В **горячем цикле верификации налива (`VERIFYING_FILL`)** — опрос ведется **исключительно** из реактивного локального кэша вебсокетов (`get_executed_position`) с нулевой задержкой сети. Никаких медленных REST-запросов на горячем пути.
  - Если обе ноги залиты (`>= min_fill_rate`) — статус переходит в `ACTIVE_HEDGED`, и сделка сопровождается дальше.
  - Если принимается решение "свернуть удочки" (не налило, несимметричный налив, ошибка отправки) — бот **перед завершением торговой итерации и сбросом статы ОБЯЗАН** выполнить точечный параллельный REST GET-запрос посимвольно по участвовавшим биржам. Если обнаружен зависший остаток — он **дозакрывается маркетом** до подтвержденного `0.0`.

## 2. Ювелирная точность точечных REST GET-запросов (`API/orders.py`)
- **Kucoin:** Эндпоинт изменен с общего тяжелого листинга всех позиций аккаунта `/api/v1/positions` на точечный запрос одиночной позиции `/api/v1/position?symbol={symbol}&positionSide={side}`.
  *(Критический нюанс: в Hedge Mode Kucoin требует параметр `positionSide=LONG` или `positionSide=SHORT`. Без него биржа возвращает `positionSide: BOTH, currentQty: 0`, что приводило к ложному 0.0!).*
- **Bitget:** Точечный эндпоинт `/api/v2/mix/position/single-position?productType=USDT-FUTURES&symbol={symbol}&marginCoin=USDT`.
- **Binance:** Точечный эндпоинт `/fapi/v2/positionRisk?symbol={symbol}`.

## 3. Интерпретаторы WS (по эталону `ARB_FUNDING_BOT`)
- **Binance (`API/BINANCE/ws_private_binance.py`):**
  Интерпретатор переведен на проверенную логику из `ARB_FUNDING_BOT`:
  - Обработка `ACCOUNT_UPDATE` (поддержка `pa > 0` для LONG, `pa < 0` для SHORT при режиме `BOTH`, мгновенное обнуление при `pa == 0`).
  - Обработка `ORDER_TRADE_UPDATE` (`FILLED`, `PARTIALLY_FILLED`, учет `reduceOnly` флага `R` для мгновенного обнуления).
- **Kucoin (`API/KUCOIN/ws_private_kucoin.py`):**
  Подписка на глобальный приватный топик матчинга `/contractMarket/tradeOrders` (вместо неработающего `/contract/position:all`), позволяющий моментально перехватывать реальные сделки матчинг-движка с объемом и ценой.
